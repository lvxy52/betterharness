# BetterHarness — 通用 AI 全栈项目骨架

**中文** | [English](./README.en.md)

> 面向「AI 辅助全栈开发」的**空骨架**：只有目录结构与 README，不含任何示例代码，不预设技术栈。
> 典型用法：复制本骨架 → 引入成熟开源框架源码（pig / yudao 等）或从零自研 → AI 按 [AGENTS.md](./AGENTS.md) 协作开发。

---

## 1. 骨架解决什么问题

| 问题 | 本骨架的做法 |
|------|-------------|
| 开源框架只有代码，文档 / 测试 / 部署无处安放 | 提供与技术栈无关的通配外围结构 |
| 各框架前后端结构不一，无法统一规定 | backend/ frontend/ 只占位，内部结构跟随引入的源码 |
| AI 开发需要稳定的协作约定 | AGENTS.md 作为唯一工作手册，主流 AI 工具自动读取 |

## 3. 上手（以引入开源框架为例）

1. **复制**本骨架为新项目根，改项目名与定位一节。
2. **引入源码**：后端源码放 backend/、前端源码放 frontend/；框架自带的多模块布局原样保留，不强行改组。
3. **填 AGENTS.md**：技术栈、构建命令、模块边界、权限模型等占位。
4. **文档先行**：docs/prd（需求）→ docs/api（契约）→ docs/plan（计划与验收）。
5. **初始化仓库**：git init + 首次提交。

---

## 4. 演进原则

1. **结构按需生长**：开发中可随时增删目录，不追求骨架完整性；增删后同步 README 索引。
2. **目录即文档**：保留的每个目录都有 README，说明职责与维护规则。
3. **单一维护原则**：每个事实只在一处维护，其它位置只链接不复制。
4. **文档先行**：字段 / 菜单 / 权限 / 流程变更，先改文档再改代码（或同步提交）。
