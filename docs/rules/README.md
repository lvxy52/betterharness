# rules/ — 开发规范

> **强制约束。** 写代码前必读，Code Review 对照。若认为某条不合理，主动提出讨论后更新本目录；**不得静默无视、按个人习惯写代码。**

## 标准文件清单（生成项目时创建）

| 文件 | 适用范围 |
|------|----------|
| `BACKEND_DEV_RULES.md` | 后端：分层、校验、异常、SQL、性能、脱敏、跨模块调用 |
| `FRONTEND_DEV_RULES.md` | 前端：目录边界、封装组件使用、字典、表单、状态管理 |
| `SELF_TEST_CHECKLIST.md` | 转测前自测清单：异常输入、编辑回显闭环、脱敏检查、导入异常矩阵、大数据量 |
| `GIT_WORKFLOW.md` | 分支与提交规范：分支命名、Commit 约定、PR / 合并流程 |

## 规范分档

| 档 | 含义 |
|----|------|
| 【必须】 | 强约束，违反即打回 |
| 【推荐】 | 默认做法，偏离需说明 |
| 【参考】 | 可选优化 |

## 约定

- 规范条文只在本地维护；README / 注释不复制条文，只链接。
- 团队原始规范（docx 等）融入 MD 后归档，**冲突以 MD 为准**。
