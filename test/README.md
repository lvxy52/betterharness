# test/ — 自动化测试

> 跨端 E2E 与验收自动化。推荐路线：**Playwright + Python**（浏览器 E2E）；纯接口验证走 API-first（快且稳）。
> 单元 / 组件测试随代码工程走（backend / frontend 内），不放本目录。

## 组织方式

- 按迭代版本隔离：`v<X.Y>/`，内部建议含 `scripts/ data/ screenshots/ results/ reports/`；新版本整目录复制，产物隔离。
- 具体结构按需生长，以实际测试方案为准。

## 核心纪律

- **账号不依赖项目预置**：种子账号 + 动态创建，唯一字段（手机号等）时间戳生成。
- 用例状态四值：**通过 / 失败 / 阻塞 / 跳过**；**卡住即跳过并记录原因**，不硬磕。
- 重跑前清理 results 与 screenshots，避免新旧混读。
- 调试三板斧：加截图、监听 API 响应、看前端源码确认组件结构，**不猜**。
- 测试账号唯一维护处在 [docs/plan 验收指南](../docs/plan/README.md)。
